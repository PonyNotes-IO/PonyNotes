# 黑屏问题处理过程总结

## 问题概述
在添加新工作区时出现黑屏问题，涉及多个层面的错误，包括后端服务、前端UI和系统集成问题。

## 问题处理时间线

### 第一阶段：构建和依赖问题
**问题**：`Blocking waiting for file lock on build directory`
- **原因**：多个构建进程同时运行导致文件锁冲突
- **解决**：识别并终止冲突的构建进程，使用正确的 `cargo make` 命令

### 第二阶段：AI/Embedding服务问题
**问题**：`LocalEmbeddingNotReady` 错误导致黑屏
- **根本原因**：Ollama服务未启动，AI嵌入功能不可用
- **解决步骤**：
    1. 安装并启动Ollama：`brew install ollama && brew services start ollama`
    2. 拉取必需模型：`ollama pull nomic-embed-text` 和 `ollama pull llama3.1:latest`
    3. 修复代码中的死锁问题：重构 `full_indexed_data_provider.rs` 中的异步操作
    4. 改进错误处理：让 `EmbeddingFullIndexConsumer` 优雅处理服务不可用的情况

### 第三阶段：代码生成问题
**问题**：`flowy_svgs.g.dart` 文件显示为"红色"（编译错误）
- **原因**：代码生成文件过期或缺失
- **解决**：运行 `./scripts/code_generation/generate.sh --verbose` 重新生成文件

### 第四阶段：视图初始化时序问题
**问题**：`Can't find the view with id: xxx` 错误
- **根本原因**：视图创建和设置当前视图的时序问题
- **解决**：
    1. 增加Flutter端重试机制：从5次重试增加到10次，延迟从200ms增加到500ms
    2. 修复Rust后端递归调用：避免 `get_current_view` 和 `set_current_view` 之间的循环调用
    3. 实现智能回退机制：当当前视图不存在时，自动查找可用的公共视图

### 第五阶段：Flutter UI生命周期问题
**问题**：`flowy_overlay.dart` 断言失败 `'_dependents.isEmpty': is not true`
- **原因**：Widget销毁时依赖项未正确清理
- **解决**：
    1. 添加 `dispose` 方法：正确清理 `_overlayList` 和 `_keyboardShortcutBindings`
    2. 移除不必要的 `MaterialApp` 包装：避免重复创建导致依赖项问题
    3. 添加 `mounted` 检查：防止在已销毁的Widget上执行操作

### 第六阶段：Navigator状态冲突问题
**问题**：`'!_debugLocked': is not true` Navigator断言失败
- **原因**：多个地方同时调用 `Navigator.of(context).pop()` 导致状态冲突
- **解决**：
    1. 使用 `SchedulerBinding.addPostFrameCallback` 确保导航操作在正确时机执行
    2. 协调不同组件的导航操作：让BlocListener统一处理对话框关闭
    3. 添加 `context.mounted` 检查：防止异步操作中的上下文问题

## 关键技术修复点

### 后端修复
1. **异步操作优化**：重构了 `full_indexed_data_provider.rs` 中的锁管理
2. **错误处理改进**：让AI服务不可用时应用仍能正常运行
3. **视图管理优化**：修复了视图查找和设置的递归调用问题

### 前端修复
1. **重试机制增强**：增加了工作区设置请求的重试次数和延迟
2. **生命周期管理**：正确清理Overlay和Navigator的依赖项
3. **状态协调**：避免多个组件同时操作Navigator状态

### 系统集成修复
1. **服务依赖**：确保Ollama和向量数据库正确初始化
2. **代码生成**：重新生成过期的Flutter代码文件
3. **Git权限**：修复了代码推送的认证问题

## 最终结果
- ✅ 工作区创建功能正常工作
- ✅ 不再出现黑屏问题
- ✅ AI功能正常集成
- ✅ UI组件生命周期管理正确
- ✅ 代码可以正常推送到仓库

## 经验总结
1. **系统性调试**：黑屏问题往往涉及多个层面，需要从后端服务到前端UI全面排查
2. **时序问题**：异步操作和UI状态管理需要特别注意时序
3. **依赖管理**：外部服务（如Ollama）的初始化对应用功能至关重要
4. **生命周期管理**：Flutter Widget的正确清理是避免内存泄漏和状态冲突的关键
5. **状态协调**：多个组件操作同一状态时需要良好的协调机制

这次问题处理展示了复杂应用调试的完整流程，从基础设施到应用逻辑，从后端服务到前端UI的全栈调试能力。
